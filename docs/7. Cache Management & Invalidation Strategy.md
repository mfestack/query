## ⚙️ Cache Management & Invalidation Strategy

### 1. Overview

Trong **MFEStack Query Core**, *cache* không chỉ là bộ nhớ tạm của dữ liệu — nó là *active state layer* giúp đảm bảo:

* dữ liệu nhất quán giữa UI và network,
* hiệu suất tối ưu qua reuse & deduplication,
* khả năng tự phục hồi (resilience) khi offline hoặc refetch lỗi.

Cấu trúc caching được lấy cảm hứng từ **TanStack Query**, nhưng được thiết kế lại để:

* tách biệt cache management khỏi client,
* hỗ trợ nhiều chiến lược invalidation,
* mở rộng dễ dàng cho plugin hoặc multi-source sync.

### 2. Core Components

| Module                    | Responsibility                                           |
| ------------------------- | -------------------------------------------------------- |
| **QueryCache.ts**         | Lưu trữ, tìm kiếm và quản lý vòng đời của tất cả queries |
| **MutationCache.ts**      | Ghi nhớ và retry mutations chưa hoàn tất                 |
| **QueryManager.ts**       | Xử lý refetch, invalidate, reset cache                   |

| **GarbageCollector (GC)** | Xoá bỏ query không còn được reference hoặc quá hạn       |

### 3. Cache Structure

```ts
interface QueryCacheMap {
  [queryHash: string]: Query;
}

class QueryCache {
  queries = new Map<string, Query>();
  subscriptions = new Set<Function>();
}
```

Mỗi query được nhận diện bằng **queryHash** (tạo từ `queryKey` + `queryFn` args).
Mỗi `Query` chứa đầy đủ state, observers và metadata:

```ts
interface QueryState {
  data?: TData;
  status: 'idle' | 'loading' | 'success' | 'error';
  error?: unknown;
  fetchStatus: 'idle' | 'fetching' | 'paused';
  updatedAt: number;
  staleTime?: number;
}
```

---

### 4. Cache Lifecycle

```text
create → fetch → success/error → update → invalidate → garbage collect
```

#### 4.1. Creation

* Khi `fetchQuery()` được gọi, QueryClient tìm hoặc tạo `Query` mới trong `QueryCache`.
* Nếu đã tồn tại → reuse, tránh refetch không cần thiết.

#### 4.2. Fetching

* Trạng thái chuyển `fetchStatus = "fetching"`.
* Kết quả lưu vào cache → observers được notify qua `QueryObserver`.

#### 4.3. Update

* Khi data mới → merge thông qua **structural sharing** (`replaceEqualDeep`) để giảm re-render.

#### 4.4. Invalidate

* Khi `invalidateQueries()` được gọi, Query chuyển sang trạng thái “stale”.
* Các observer có thể trigger refetch ngay hoặc chờ `refetchOnWindowFocus`.

#### 4.5. Garbage Collection

* Khi không còn observer nào → bắt đầu countdown `cacheTime`.
* Hết thời gian → query bị remove khỏi cache.
* GC được điều phối bởi `NotifyManager` để đảm bảo batch delete.

---

### 5. Invalidation Strategy

#### 5.1. Key-based Invalidation

Cho phép invalidate theo `queryKey` hoặc pattern (prefix match).

```ts
client.invalidateQueries(['users']); // invalidate all 'users/*'
```

#### 5.2. Predicate-based Invalidation

Dựa trên điều kiện logic để xác định query nào cần invalidate.

```ts
client.invalidateQueries({
  predicate: (query) => query.state.data?.isArchived === true
});
```

#### 5.3. Event-based Invalidation

Kết hợp với plugin hoặc mutation để tự động invalidate khi mutation thành công.

```ts
client.setMutationDefaults('updateUser', {
  onSuccess: () => client.invalidateQueries(['users'])
});
```

#### 5.4. TTL-based Invalidation

Tự động đánh dấu stale sau `staleTime` đã định nghĩa trong `defaultOptions.ts`.

```ts
staleTime = 5 * 60 * 1000; // 5 phút
```

---

### 6. Garbage Collection (GC)

MFEStack có cơ chế GC tương tự TanStack, nhưng tinh chỉnh linh hoạt hơn:

* GC chạy **lazy** theo tick của `NotifyManager`.
* Mỗi query có `cacheTime` riêng (hoặc global default).
* Khi query bị unsubscribe → countdown GC.
* Khi có observer mới → hủy countdown.

```ts
if (query.observers.length === 0) {
  scheduleGC(query, query.cacheTime);
}
```

#### 6.1. Adaptive GC

GC được điều chỉnh theo **memory pressure** (qua plugin hoặc browser API).
Ví dụ: khi `navigator.deviceMemory < 2GB`, giảm `cacheTime` mặc định.

---

### 7. Cache Deduplication

MFEStack triển khai **request deduplication** ở tầng `QueryManager` và `Retryer`:

* Nếu nhiều observer yêu cầu cùng `queryKey` → chỉ fetch một lần.
* Các observer khác sẽ subscribe vào cùng `Query`.
* Kết quả được chia sẻ, tránh lặp HTTP call.

```ts
if (query.isFetching) {
  return query.addObserver(observer);
}
```

---

### 8. Cache Rehydration & Persistence Interaction

Khi kết hợp với **Persistence Layer**:

* Cache được rehydrate từ snapshot khi app khởi động.
* GC bỏ qua các query chưa hết hạn.
* Khi broadcast hoặc sync diễn ra → merge lại state nếu timestamp mới hơn.

### 10. Future Enhancements

* **Priority-based GC:** ưu tiên giữ query critical (e.g. authenticated user).
* **LRU Cache Mode:** xoá query cũ nhất khi vượt giới hạn bộ nhớ.
* **Segmented Cache:** cho phép chia cache theo domain logic (e.g. “session”, “shared”, “analytics”).
* **Background Eviction Scheduler:** chạy định kỳ trong idle time để tối ưu bộ nhớ.
