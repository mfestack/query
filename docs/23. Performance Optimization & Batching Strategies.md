# ⚡ Performance Optimization & Batching Strategies

**Modules:** `NotifyManager`, `BatchManager`, `scheduler`, `QueryObserver`, `MutationObserver`, `replaceEqualDeep`

---

## 1️⃣ Overview

MFEStack Query Core được thiết kế với triết lý **“predictable reactivity + minimal re-render”**, nghĩa là mọi hoạt động cập nhật dữ liệu đều được gom, tối ưu và chỉ kích hoạt lại UI khi thật sự cần thiết.

Mục tiêu của tầng tối ưu hiệu năng là:

* Giảm **render frequency**.
* Loại bỏ **duplicated requests**.
* Tối ưu **cache comparison** với structural sharing.
* Điều phối các tác vụ nền và thông báo qua **NotifyManager**.

---

## 2️⃣ Key Optimization Concepts

### 🔹 **Batching**

Gom nhiều cập nhật (cache, observer, event) trong cùng một tick để giảm re-render.

### 🔹 **Deduplication**

Nếu có nhiều query cùng key, chúng dùng chung fetch request, tránh gọi lại API không cần thiết.

### 🔹 **Memoization**

Dữ liệu được giữ nguyên reference nếu không thay đổi (deep-equal), giúp tránh render lại ở UI layer.

### 🔹 **Scheduling**

Các task nền (refetch, retry, invalidate) được lập lịch hợp lý để tránh nghẽn main thread.

## 3️⃣ BatchManager

`BatchManager.ts` chịu trách nhiệm gom và điều phối update.
Mỗi event (`success`, `error`, `refetch`) không bắn trực tiếp mà đi qua `batchNotify()`:

```ts
notifyManager.batch(() => {
  queryObserver.onSuccess(data)
  queryObserver.onSettled(data, null)
})
```

Cơ chế này đảm bảo:

* Tối đa 1 re-render mỗi tick.
* Dễ mở rộng plugin intercept notification.
* Giảm chi phí xử lý khi có hàng loạt query cập nhật cùng lúc.

---

## 4️⃣ NotifyManager

`NotifyManager.ts` là scheduler điều phối batching.
Khi nhiều query/mutation cần update, chúng sẽ được queue lại:

```ts
class NotifyManager {
  private queue = new Set<Function>()
  
  batch(fn: Function) {
    this.queue.add(fn)
    requestAnimationFrame(() => this.flush())
  }

  flush() {
    this.queue.forEach(fn => fn())
    this.queue.clear()
  }
}
```

→ Việc dùng `requestAnimationFrame()` hoặc `scheduler.postTask()` giúp đảm bảo event chạy **sau khi browser idle**, tối ưu hiệu năng UI.

## 5️⃣ Deduplication Strategy

`QueryManager` kiểm tra cache trước khi tạo request mới:

```ts
if (queryCache.has(key)) {
  return existingQuery.promise
}
```

Nếu query đang fetch, MFEStack tự động **join promise** hiện tại thay vì tạo mới.
→ Tối ưu 50–80% số request song song bị trùng lặp.

## 6️⃣ Structural Sharing Optimization

`replaceEqualDeep.ts` là chìa khóa để giữ ổn định reference khi dữ liệu không đổi:

```ts
export function replaceEqualDeep(oldValue, newValue) {
  if (shallowEqual(oldValue, newValue)) return oldValue
  if (Array.isArray(newValue)) return newValue.map(...)
  return newValue
}
```

Điều này đảm bảo:

* UI không re-render khi dữ liệu “bằng nhau về logic”.
* Dữ liệu lớn (arrays, objects) được chia sẻ lại reference cũ khi không đổi.

## 7️⃣ Scheduler Integration

MFEStack sử dụng `scheduler.ts` để lập lịch cho refetch, retry, GC và plugin update:

| Task Type     | Scheduling Method             | Priority |
| ------------- | ----------------------------- | -------- |
| Refetch       | `postTask()` / `setTimeout()` | Normal   |
| Retry         | Exponential backoff delay     | High     |
| GC Cleanup    | `requestIdleCallback()`       | Low      |
| DevTools sync | `rafBatch()`                  | Normal   |

Điều này giúp:

* Tối ưu main thread.
* Giữ tính responsive của UI.
* Hạn chế block event loop khi nhiều query cùng refetch.

## 9️⃣ Plugin Hook Integration

MFEStack mở rộng khả năng quan sát performance bằng hook:

```ts
pluginManager.hook('onBatchStart', { count })
pluginManager.hook('onTaskDeferred', { task, delay })
pluginManager.hook('onRenderSkipped', { queryKey })
```

Các plugin như `devtoolsPlugin` có thể log hoặc hiển thị performance metrics theo thời gian thực.
