
## 📊 **Hydration, Serialization & SSR Integration**

### **1. Overview**

Hydration trong **MFEStack Query Core** là quá trình **đồng bộ hóa cache** giữa **server-side render (SSR)** và **client-side render (CSR)**.
Mục tiêu là đảm bảo dữ liệu **không bị refetch không cần thiết** sau khi trang được render lần đầu, đồng thời **duy trì tính toàn vẹn (consistency)** giữa hai môi trường.

Hệ thống hydration của MFEStack được thiết kế để:

* Tách biệt hoàn toàn **cache state** khỏi client runtime.
* Cho phép **multi-client hydration** (React, Vue, Svelte, Solid).
* Hỗ trợ **plugin persistence** (localStorage, IndexedDB) để preload dữ liệu trước khi khởi chạy client.
* Tích hợp với **structural sharing** và **event system** để đảm bảo consistency ngay cả sau khi rehydrate.

---

### **2. Architecture Components**

Hydration được triển khai trong thư mục `core/src/hydration/` với 3 module chính:

| File                | Purpose                                                                   |
| ------------------- | ------------------------------------------------------------------------- |
| `dehydrate.ts`      | Chuyển đổi `QueryCache` & `MutationCache` thành object JSON serializable. |
| `hydrate.ts`        | Khôi phục lại cache từ dữ liệu đã serialize.                              |
| `hydrationUtils.ts` | Cung cấp helpers (validate, merge strategy, context mapping).             |

Ngoài ra, `QueryClient` có thêm hook nội bộ:

```ts
client.dehydrate(options?: DehydrateOptions)
client.hydrate(state: DehydratedState)
```

---

### **3. Dehydration Process (Server → JSON)**

Trên server, trước khi gửi HTML về client, MFEStack thực hiện quá trình **dehydrate**:

```ts
import { dehydrate } from '@mfestack/core/hydration'
const dehydratedState = dehydrate(queryClient, {
  shouldDehydrateQuery: (query) => query.state.status === 'success',
  includeMutations: false
})
```

Kết quả là một JSON có cấu trúc:

```json
{
  "queries": [
    {
      "queryKey": ["user", 1],
      "state": {
        "data": { "id": 1, "name": "Alice" },
        "status": "success",
        "fetchStatus": "idle",
        "updatedAt": 1698550000
      }
    }
  ],
  "mutations": []
}
```

Sau đó, `dehydratedState` được embed vào HTML:

```html
<script id="__APPSTACK_STATE__" type="application/json">
  {...dehydratedState}
</script>
```

---

### **4. Hydration Process (Client Rebuild)**

Khi client khởi chạy, MFEStack đọc state từ script và phục hồi lại cache:

```ts
import { hydrate } from '@mfestack/core/hydration'
import { QueryClient } from '@mfestack/core'

const client = new QueryClient()
const dehydratedState = JSON.parse(
  document.getElementById('__APPSTACK_STATE__').textContent
)
hydrate(client, dehydratedState)
```

Cơ chế hydration:

1. Tạo lại `Query` và `Mutation` từ dữ liệu JSON.
2. Khôi phục `data`, `status`, `error`, `meta`.
3. Gắn observer vào mỗi query (nếu có active subscription).
4. Kích hoạt structural merge nếu cache hiện có dữ liệu cũ.

---

### **5. Structural Merge & Conflict Resolution**

MFEStack hỗ trợ **merge strategy** khi client đã có cache cục bộ:

* **PreferServer:** luôn ghi đè từ SSR.
* **PreferClient:** chỉ hydrate nếu client chưa có dữ liệu.
* **MergeStructural:** kết hợp `replaceEqualDeep` để hòa trộn dữ liệu.

Ví dụ:

```ts
hydrate(client, dehydratedState, { strategy: 'mergeStructural' })
```

Điều này hữu ích khi:

* Người dùng có cache offline cũ.
* Ứng dụng sử dụng multi-tab cache broadcast.
* Có sự chênh lệch dữ liệu do session timeout.

---

### **6. Multi-Client & Framework Hydration**

MFEStack hỗ trợ **adapter-level hydration API** cho từng framework:

| Framework  | API                                                                         |
| ---------- | --------------------------------------------------------------------------- |
| **React**  | `<Hydrate state={dehydratedState}><App /></Hydrate>`                        |
| **Vue**    | `<Hydrate :state="dehydratedState"><App /></Hydrate>`                       |
| **Svelte** | `hydrateClient(queryClient, dehydratedState)`                               |
| **Solid**  | `<HydrationBoundary state={dehydratedState}>{children}</HydrationBoundary>` |

Mỗi adapter ánh xạ tới cùng core API (`hydrate`, `dehydrate`) nhưng quản lý context và lifecycle phù hợp framework tương ứng.

---

### **7. Persistence Integration**

Khi persistence plugin được bật (VD: `persistPlugin.ts`), hydration có thể kết hợp để **phục hồi dữ liệu từ localStorage/IndexedDB** trước khi hydrate từ SSR.

Thứ tự ưu tiên:

1. SSR state (server)
2. Persisted state (offline/local)
3. Realtime broadcast (multi-tab)

Ví dụ:

```ts
const persisted = await persistPlugin.restore()
const serverState = JSON.parse(window.__APPSTACK_STATE__)
hydrate(client, persisted ?? serverState)
```

---

### **8. SSR Compatibility Layer**

MFEStack có module `isServer.ts` giúp phát hiện môi trường SSR:

```ts
export const isServer = typeof window === 'undefined'
```

Điều này được dùng trong:

* QueryClient để disable auto-refetch khi SSR.
* Retryer để skip retry trong môi trường không có network.
* NotifyManager để tránh gọi observer khi chưa mount UI.

Khi SSR:

* Tất cả query fetch được thực thi **synchronously** trước khi render.
* Cache được serialize ngay sau khi hoàn thành render HTML.
* Không có bất kỳ refetch nào cho đến khi client hydrate hoàn tất.

### **10. Summary**

MFEStack Query Core cung cấp một cơ chế **Hydration toàn diện**, kết hợp giữa:

* **Serialization an toàn & nhỏ gọn**,
* **Structural Sharing thông minh**,
* **Multi-client cache merging**,
* Và **plugin persistence/broadcast integration**.

Nhờ đó, MFEStack có thể xử lý dữ liệu SSR/CSR liền mạch, giảm thiểu refetch, đồng thời duy trì data consistency trong mọi tình huống — kể cả đa framework hoặc môi trường offline-first.
