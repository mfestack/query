# 🚨 Error Handling & Retry Strategy

**Modules:** `Retryer`, `QueryManager`, `MutationObserver`, `NotifyManager`
**Related Components:** `defaultOptions`, `scheduler`, `loggerPlugin`

---

## 1️⃣ Overview

MFEStack Query Core cung cấp một **error handling system** thống nhất cho cả **query** và **mutation**, đảm bảo tính ổn định và khả năng phục hồi trong môi trường mạng không đáng tin cậy.
Cấu trúc này được thiết kế theo mô hình **“resilient data fetching”**, tương tự TanStack Query, nhưng mở rộng thêm các khả năng sau:

* Retry logic thông minh với **exponential backoff + jitter**.
* Multi-layer error context (client, observer, plugin).
* Integration với plugin `logger`, `persist`, và `broadcast` để đảm bảo khả năng giám sát và đồng bộ lỗi.

---

## 2️⃣ Error Lifecycle

### 🔄 Query Error Flow

1. `QueryManager.fetchQuery()` gọi fetch function.
2. Nếu fetch throw error → `Retryer` khởi tạo retry loop.
3. Sau khi vượt quá `retryCount`, trạng thái query chuyển sang `error`.
4. `QueryObserver` thông báo client qua event `"error"`.
5. `loggerPlugin` và `devtoolsPlugin` có thể intercept để hiển thị hoặc ghi log.

### 🧩 Mutation Error Flow

1. Mutation gọi `executeMutation()`.
2. Nếu thất bại → kích hoạt `Retryer`.
3. Khi hết `retryLimit`, mutation được đánh dấu `failed`.
4. Nếu `onError` hoặc `onSettled` được định nghĩa, chúng được gọi kèm metadata lỗi.

## 3️⃣ Retry Strategy

MFEStack sử dụng module `Retryer.ts` với cấu hình đầy đủ:

| Option             | Description                                   | Default                            |
| ------------------ | --------------------------------------------- | ---------------------------------- |
| `retry`            | Số lần retry tối đa (số hoặc boolean)         | `3`                                |
| `retryDelay`       | Hàm hoặc số xác định delay giữa các lần retry | `(attempt) => 1000 * 2 ** attempt` |
| `backoffFactor`    | Hệ số nhân delay cho exponential backoff      | `2`                                |
| `jitter`           | Random ±10% delay để tránh spike              | `true`                             |
| `networkSensitive` | Chỉ retry khi online                          | `true`                             |
| `focusSensitive`   | Tạm dừng retry nếu window không focus         | `true`                             |

---

## 4️⃣ Retryer Design

`Retryer` là một **finite-state controller** điều phối retry sequence:

```
Idle → Pending → Retrying → Success | Failed
```

Mỗi lần retry đều tạo một promise chain kèm delay, được `scheduler` điều phối nhằm tránh block main thread.

Ví dụ luồng hoạt động:

```ts
const retryer = new Retryer({
  fn: fetchFn,
  retry: 3,
  retryDelay: exponentialBackoff,
  onSuccess: handleSuccess,
  onFail: handleFailure,
})
retryer.start()
```

---

## 5️⃣ Adaptive Retry (Enhanced Feature)

MFEStack mở rộng retry cơ bản bằng cơ chế **adaptive retry**:

* Nếu server trả về mã lỗi 5xx → áp dụng exponential backoff.
* Nếu là lỗi 4xx (client error) → dừng retry ngay.
* Nếu là lỗi `NetworkError` → delay ngẫu nhiên (jittered backoff).
* Nếu có plugin `onlineManager` → suspend retry cho đến khi có mạng.

Điều này giúp MFEStack ổn định hơn khi chạy trên mạng chập chờn (mobile, offline-first app).

## 6️⃣ Plugin Integration Hooks

MFEStack cho phép hook vào các giai đoạn lỗi thông qua plugin:

| Hook                 | Trigger                    | Payload                 |                      |
| -------------------- | -------------------------- | ----------------------- | -------------------- |
| `onRetryStart(query  | mutation)`                 | Bắt đầu retry           | `{ attempt, delay }` |
| `onRetrySuccess()`   | Retry thành công           | `{ attempt, duration }` |                      |
| `onRetryFailure()`   | Retry thất bại hoàn toàn   | `{ attempts, error }`   |                      |
| `onNetworkSuspend()` | Tạm ngừng do mất mạng      | `{ queryKey }`          |                      |
| `onNetworkResume()`  | Tiếp tục retry khi có mạng | `{ queryKey }`          |                      |

## 7️⃣ Observer Notification System

Tất cả event lỗi hoặc retry đều được phát qua `NotifyManager`, đảm bảo:

* Không có re-render dư thừa.
* Batch nhiều thông báo lại cùng một tick.
* Cho phép framework adapter (React/Vue/...) cập nhật UI an toàn.

```ts
notifyManager.batch(() => {
  observer.onError(error)
  observer.onSettled(error, null)
})
```

---

## 8️⃣ Error Boundary Integration (Framework Layer)

Adapter như `@mfestack/react` hay `@mfestack/vue` có thể tận dụng error propagation qua hook `useQueryErrorResetBoundary` hoặc context API:

```ts
<QueryErrorBoundary>
  <Component />
</QueryErrorBoundary>
```

Điều này giúp tách logic retry ra khỏi UI component.

## ✅ Summary

MFEStack Query Core cung cấp hệ thống **error & retry** mạnh mẽ, tương thích 100% với TanStack nhưng được mở rộng để:

* Hỗ trợ retry thông minh theo loại lỗi.

* Có khả năng thích ứng với môi trường network thay đổi.

Kết quả là hệ thống resilient hơn, **tối ưu trải nghiệm người dùng và giảm thiểu lỗi không mong muốn** trong ứng dụng đa framework.
