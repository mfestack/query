## 🧮 Metrics & Performance Telemetry (Tracing, Instrumentation & Observability)

### 1️⃣ Overview

Hệ thống Metrics & Telemetry trong core đóng vai trò ghi nhận **hiệu suất, tần suất truy vấn, cache hit/miss**, và trạng thái hoạt động của từng plugin hoặc fetcher. Mục tiêu là giúp developers quan sát **health status** của toàn bộ query ecosystem mà không làm ảnh hưởng đáng kể đến performance runtime.

### 2️⃣ Core Principles

* **Lightweight Metrics Collection:** thu thập dữ liệu trong bộ nhớ tạm (in-memory ring buffer) thay vì gửi log trực tiếp.
* **Non-blocking Instrumentation:** tất cả metric hooks chạy trong microtask queue để tránh chặn luồng UI hoặc network.
* **Extensible Exporters:** cho phép plugin định nghĩa custom exporter (ví dụ gửi dữ liệu sang OpenTelemetry, Prometheus hoặc custom dashboard).
* **Configurable Granularity:** mức chi tiết metric (low/high) có thể thay đổi bằng environment hoặc runtime config.

### 3️⃣ Core Metrics

| Metric                       | Description                                 | Default Sampling |
| ---------------------------- | ------------------------------------------- | ---------------- |
| `fetch_time_avg`             | Thời gian trung bình hoàn tất 1 fetch cycle | 100%             |
| `cache_hit_ratio`            | Tỷ lệ query trả về từ cache                 | 50%              |
| `stale_query_count`          | Số query hết hạn nhưng chưa bị refetch      | 100%             |
| `background_refetch_latency` | Độ trễ khi background scheduler kích hoạt   | 25%              |
| `plugin_exec_duration`       | Thời gian trung bình thực thi plugin hooks  | 100%             |
| `network_retry_attempts`     | Tổng số lần retry trong vòng 10 phút        | 100%             |

### 4️⃣ Architecture

```
[Query Core] --> [Metric Collector] --> [Metric Buffer] --> [Exporter Bus] --> [Adapters: Console | Prometheus | OTEL | Custom]
```

* **Metric Collector:** Ghi nhận các sự kiện từ query lifecycle (fetch, success, error, invalidate…).
* **Metric Buffer:** Lưu dữ liệu theo dạng circular buffer để tránh memory leak.
* **Exporter Bus:** Là một event bus nội bộ, dùng pattern `Observer` để plugin hoặc external exporter có thể subscribe metric stream.

### 5️⃣ Tracing Integration

* Hỗ trợ **OpenTelemetry Tracing API** nếu environment có sẵn.
* Mỗi query operation có thể tạo một **trace span** gồm các sub-event:

  * `fetch_start` → `cache_check` → `network_request` → `parse_response` → `store_update`.
* Cho phép correlate trace ID với logs hoặc metric entries để theo dõi toàn pipeline.

### 6️⃣ Developer Hooks

```ts
const unsubscribe = core.observeMetrics((metric) => {
  if (metric.name === "cache_hit_ratio" && metric.value < 0.6) {
    console.warn("Low cache hit ratio detected:", metric.value);
  }
});
```

Hoặc:

```ts
core.exportMetrics({ to: "console", filter: ["fetch_time_avg", "network_retry_attempts"] });
```

### 7️⃣ AppStack Metrics (Current API)

The core exposes a lightweight in-memory metrics registry, attached to `QueryClient` and powered by `EventBus`.

#### Snapshot shape

```ts
type MetricsSnapshot = {
  queriesFetched: number
  queriesSucceeded: number
  queriesFailed: number
  cacheInvalidations: number
  cacheClears: number
  mutationsStarted: number
  mutationsSucceeded: number
  mutationsFailed: number
  lastUpdatedAt: number
}
```

#### Consuming in core

```ts
import { QueryClient } from '@mfestack/core'

const client = new QueryClient()
const snap = client.metrics.getSnapshot()
const unsubscribe = client.metrics.subscribe((next) => {
  // react to updates
})
```

#### Consuming in React

```tsx
import { useMetrics } from '@mfestack/react'

function MetricsWidget() {
  const m = useMetrics()
  return (
    <div>
      <div>Fetched: {m.queriesFetched}</div>
      <div>Success: {m.queriesSucceeded}</div>
      <div>Failed: {m.queriesFailed}</div>
      <div>Mutations: {m.mutationsStarted}</div>
    </div>
  )
}
```

#### Event mapping

- `query:updated` → `queriesFetched` (+ also increments `queriesSucceeded` or `queriesFailed` based on `state.status`)
- `cache:invalidated` → `cacheInvalidations`
- `cache:cleared` → `cacheClears`
- `mutation:started` → `mutationsStarted`
- `mutation:success` → `mutationsSucceeded`
- `mutation:error` → `mutationsFailed`

#### Notes

- Emission uses `EventBus` with microtask/idle scheduling for non-blocking updates.
- Memory footprint is constant: counters + last timestamp. DevTools timeline is bounded (last 50 events).

### 8️⃣ Use Cases

* **Performance Tuning:** xác định plugin nào làm tăng thời gian phản hồi.
* **Cache Optimization:** phân tích tỷ lệ cache hit và stale query để điều chỉnh TTL.
* **Error Forensics:** theo dõi truy vấn lỗi nhiều lần liên tục trong khoảng thời gian ngắn.
* **Live Dashboard:** đồng bộ dữ liệu metric với real-time monitor UI để xem sức khỏe hệ thống.
