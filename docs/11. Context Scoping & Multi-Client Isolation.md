## 🧭 **Context Scoping & Multi-Client Isolation**

### **1. Overview**

Trong MFEStack Query Core, cơ chế **Context Scoping** là nền tảng cho phép tạo và quản lý **nhiều instance độc lập của `AppStackClient`**, mỗi instance đại diện cho một **context logic riêng biệt** (ví dụ: app, tab, workspace, hoặc tenant khác nhau).

Tính năng này kế thừa triết lý của `QueryClient` trong **TanStack Query**, nhưng mở rộng hơn với khả năng:

* Chia tách toàn bộ cache, mutation, event, và plugin per-client.
* Giao tiếp giữa các client thông qua **Cross-Client Bridge Layer**.
* Hỗ trợ context nhiều tầng (nested context hierarchy).

---

### **2. Design Goals**

| Goal                              | Description                                                                         |
| --------------------------------- | ----------------------------------------------------------------------------------- |
| **Isolation by Default**          | Mỗi `AppStackClient` có cache, event system, plugin riêng biệt.                     |
| **Scoped Hydration**              | Cho phép hydrate/dehydrate từng scope độc lập (SSR, workspace).                     |
| **Cross-Client Sync**             | Cho phép broadcast selective event giữa các client.                                 |
| **Multi-Context Adapter Support** | Framework adapter (React/Vue) có thể hoạt động song song trên nhiều context.        |
| **Dynamic Lifecycle**             | Client có thể được tạo hoặc hủy động trong runtime mà không ảnh hưởng global state. |

---

### **3. Core Architecture**

#### **3.1 AppStackClient**

`AppStackClient` là **đơn vị scope chính** trong MFEStack Core.

```ts
export class AppStackClient {
  readonly id: string;
  readonly scope: string;
  readonly queryCache: QueryCache;
  readonly mutationCache: MutationCache;
  readonly eventBus: EventEmitter;
  readonly pluginManager: PluginManager;
  readonly focusManager: FocusManager;
  readonly onlineManager: OnlineManager;
  
  constructor(options: ClientOptions) {
    this.id = options.id ?? uuid();
    this.scope = options.scope ?? 'default';
    this.queryCache = new QueryCache();
    this.mutationCache = new MutationCache();
    this.eventBus = new EventEmitter();
    this.pluginManager = new PluginManager();
    this.focusManager = new FocusManager();
    this.onlineManager = new OnlineManager();
  }
}
```

Mỗi instance này vận hành **hoàn toàn độc lập**, tương tự như `QueryClient` của TanStack, nhưng có thể tương tác qua một **Bridge Layer** (trình bày ở phần sau).

---

#### **3.2 Context Tree**

Một ứng dụng có thể chứa **nhiều scope con**, ví dụ:

```
App
├─ DefaultClient (scope: global)
├─ WorkspaceClient (scope: workspace-123)
│  ├─ TeamClient (scope: team-45)
│  └─ TeamClient (scope: team-67)
└─ GuestClient (scope: anonymous)
```

Mỗi scope có cache riêng nhưng có thể kế thừa **plugin** hoặc **policy** từ cha.

---

### **4. Scope Registry**

`ClientRegistry` là trung tâm quản lý tất cả `AppStackClient` đang hoạt động trong runtime.

```ts
class ClientRegistry {
  private clients = new Map<string, AppStackClient>();

  register(client: AppStackClient) {
    this.clients.set(client.scope, client);
  }

  get(scope: string) {
    return this.clients.get(scope);
  }

  broadcast(event: string, payload: any) {
    for (const client of this.clients.values()) {
      client.eventBus.emit(event, payload);
    }
  }
}
```

* Hỗ trợ **look-up client theo scope**.
* Cho phép **broadcast global event** (ví dụ: invalidate toàn hệ thống).
* Dễ dàng **tạo context mới** trong multi-tenant hoặc multi-app setup.

---

### **5. Context Lifecycle**

| Stage                     | Description                                                         |
| ------------------------- | ------------------------------------------------------------------- |
| **Initialization**        | `createQueryClient()` khởi tạo instance mới với cấu hình tùy chỉnh. |
| **Activation**            | Client được đăng ký vào `ClientRegistry`.                           |
| **Operation**             | Các query/mutation hoạt động trong phạm vi cache và event riêng.    |
| **Deactivation**          | Khi không còn observer nào, client có thể được garbage-collected.   |
| **Hydration/Dehydration** | Mỗi scope có snapshot cache riêng cho SSR/CSR.                      |

---

### **6. Scoped Hydration & Serialization**

Mỗi scope có thể hydrate/dehydrate riêng biệt, giúp SSR hiệu quả hơn trong ứng dụng đa người dùng:

```ts
// Server side
const dehydrated = dehydrate(clientWorkspace123);

// Client side
hydrate(clientWorkspace123, dehydrated);
```

Điều này tránh việc serialize toàn bộ cache global — chỉ serialize phần liên quan đến scope đang được render.

---

### **7. Cross-Client Bridge Layer**

Để giao tiếp giữa các scope (ví dụ multi-tab, multi-tenant, hoặc iframe app), MFEStack hỗ trợ **Bridge Layer** dựa trên event:

```
Client A (scope: workspace-123)
    │
    ├─ event: cache:updated
    ↓
Bridge Layer (BroadcastChannel / ServiceWorker)
    ↓
Client B (scope: workspace-123)
    └─ hydrate partial cache update
```

Điều này được triển khai qua plugin `broadcastPlugin`, giúp cache giữa các app hoặc tab **đồng bộ theo scope** mà không đụng chạm context khác.

---

### **8. Multi-Framework Context Adapters**

MFEStack hỗ trợ nhiều adapter cùng tồn tại:

* `@mfestack/react` có thể kết nối `AppStackClient(scope: 'react')`
* `@mfestack/vue` dùng client khác (`scope: 'vue'`)
* Các client có thể **chia sẻ cache chung qua broadcast layer** hoặc **hoàn toàn tách biệt**.

Điều này làm cho MFEStack phù hợp với **micro-frontend** hoặc **multi-platform environment**.

---

### **10. Summary**

* Mỗi `AppStackClient` là **một scope độc lập**, có đầy đủ query/mutation cache, event bus, plugin system.
* `ClientRegistry` quản lý toàn bộ lifecycle và broadcast.
* Hỗ trợ **cross-client sync**, **nested context**, và **scoped hydration**.
* Thiết kế này giúp MFEStack dễ dàng mở rộng cho:

  * Multi-tenant apps
  * Micro-frontend systems
  * Real-time multi-user dashboards
