# ⚙️ MFEStack Core: Lifecycle Flow

### Data Fetching, Mutation, and Cache Synchronization

---

## 1. Query Lifecycle — From Fetch to Render

MFEStack Query vận hành theo mô hình **event-driven state machine**, trong đó mỗi Query là một thực thể có vòng đời khép kín.
Quá trình bắt đầu từ việc **client yêu cầu dữ liệu**, đi qua **fetch, cache, observer**, và kết thúc ở **UI re-render**.

### 🧭 Step-by-step Sequence

```text
User/Adapter (useQuery)
       │
       ▼
QueryClient.fetchQuery(key, fn, options)
       │
       ▼
QueryCache.findOrCreateQuery(key)
       │
       ▼
QueryManager.executeFetch(queryFn)
       │
       ▼
Retryer.run(fetchFn, retryOptions)
       │
       ▼
(data/error)
       │
       ▼
QueryStateReducer → update(state)
       │
       ▼
NotifyManager.batchNotify()
       │
       ▼
QueryObserver.onChange → re-render UI
```

### 🧩 Key Modules Involved

| Module              | Vai trò          | Chi tiết                                               |
| ------------------- | ---------------- | ------------------------------------------------------ |
| `QueryClient`       | Entry point      | Gọi `fetchQuery` / `prefetchQuery`                     |
| `QueryCache`        | Lưu trữ state    | Trả về instance `Query` hiện có hoặc tạo mới           |
| `QueryManager`      | Lifecycle engine | Điều phối fetch, cancel, invalidate                    |
| `Retryer`           | Retry logic      | Backoff, cancelation, pause/resume                     |
| `QueryStateReducer` | State transition | Chuyển đổi trạng thái `idle → loading → success/error` |
| `NotifyManager`     | Batching update  | Gom và phát event để observer nhận thay đổi            |
| `QueryObserver`     | Bridge tới UI    | Trigger re-render adapter layer                        |

### 🔄 State Transition Diagram

```
        ┌──────────────┐
        │     idle     │
        └──────┬───────┘
               │ fetch
               ▼
        ┌──────────────┐
        │   loading    │
        └──────┬───────┘
      success  │   │ error
               ▼   ▼
     ┌──────────────┐
     │   success    │
     └──────────────┘
     ┌──────────────┐
     │    error     │
     └──────────────┘
```

### 🧠 Notable Features

* **Structural Sharing** (`replaceEqualDeep`) giúp tránh re-render thừa.
* **Stale/Fetching flags** giúp framework adapter xác định thời điểm cần refetch.
* **CacheTime & GC** điều chỉnh vòng đời của query trong `QueryCache`.

## 2. Mutation Lifecycle — From Trigger to State Propagation

Mutation là quá trình ghi dữ liệu, với khả năng **optimistic updates**, **rollback on failure**, và **retry policy**.
Nó chạy song song với query system nhưng có cơ chế notify riêng.

### 🔁 Sequence Flow

```text
User/Adapter (useMutation)
       │
       ▼
QueryClient.executeMutation(mutationFn, options)
       │
       ▼
MutationCache.createMutation()
       │
       ▼
MutationObserver.onStart()
       │
       ▼
Retryer.run(mutationFn)
       │
       ├── success → onSuccess(), invalidateQueries()
       │
       └── error → onError(), rollback(), retry()
       ▼
MutationStateReducer → update()
       ▼
NotifyManager.batchNotify()
       ▼
UI Update / Toast / Refetch
```

### ⚙️ Key Responsibilities

| Module             | Vai trò                                                   |
| ------------------ | --------------------------------------------------------- |
| `MutationCache`    | Giữ trạng thái mutation đang diễn ra                      |
| `MutationObserver` | Theo dõi và phát sự kiện tới adapter                      |
| `Retryer`          | Retry logic với delay và exponential backoff              |
| `NotifyManager`    | Gom update mutation-state                                 |
| `QueryClient`      | Kích hoạt `invalidateQueries` sau khi mutation thành công |

### 💡 Features

* **Optimistic update:** cập nhật UI ngay trước khi server phản hồi.
* **Rollback:** khôi phục UI khi lỗi.
* **Automatic cache invalidation:** refetch các query liên quan.

## 3. Cache Synchronization — Multi-tab & Cross-App

MFEStack hỗ trợ **realtime cache synchronization** giữa nhiều instance hoặc nhiều tab thông qua plugin.

### 🧭 Flow Overview

```text
QueryCache (Instance A)
       │
       ▼
persistPlugin / broadcastPlugin
       │
   serialize cache
       │
       ▼
localStorage / BroadcastChannel
       │
       ▼
Hydration (Instance B)
       │
       ▼
QueryCache.hydrate(dehydratedState)
```

### 🔌 Plugins Involved

| Plugin              | Chức năng                | Cơ chế                         |
| ------------------- | ------------------------ | ------------------------------ |
| **persistPlugin**   | Lưu cache giữa các phiên | LocalStorage, IndexedDB        |
| **broadcastPlugin** | Sync cache giữa tab      | `BroadcastChannel API`         |
| **devtoolsPlugin**  | Quan sát realtime state  | Hook vào NotifyManager         |
| **loggerPlugin**    | Debug lifecycle          | Lưu trace cho Query/Mute event |

### 🔄 Hydration Cycle

1. **Server:** `dehydrate(queryClient)` → serialize cache.
2. **Client:** `hydrate(queryClient, dehydratedState)` → restore lại state.
3. **Plugin:** thực thi hook `onHydrate()` và `onCacheUpdate()`.

## 4. Event Loop & Manager Interaction

MFEStack có hệ thống manager phối hợp hoạt động dựa trên browser state:

```
[OnlineManager]   → Resume fetch khi mạng trở lại
[FocusManager]    → Refetch khi tab được focus
[NotifyManager]   → Batch all UI notifications
[BatchManager]    → Gom các update để render 1 lần
```

Ví dụ:
Nếu người dùng offline trong khi query đang fetch:

* `OnlineManager` tạm dừng `Retryer`
* Khi mạng khôi phục → `Retryer.resume()`
* `NotifyManager` phát sự kiện tới `QueryObserver`
* `UI` tự động hiển thị dữ liệu mới mà không cần user tương tác.

## 5. Fetching Lifecycle Summary

| Phase              | Module chính                         | Hành động                     |
| ------------------ | ------------------------------------ | ----------------------------- |
| **Initialization** | `QueryClient`, `QueryCache`          | Khởi tạo query & observer     |
| **Fetching**       | `QueryManager`, `Retryer`            | Gọi fetcher, retry khi lỗi    |
| **Updating**       | `QueryStateReducer`, `NotifyManager` | Cập nhật state và phát notify |
| **Rendering**      | `QueryObserver`                      | Re-render UI khi có thay đổi  |
| **GC / Cleanup**   | `QueryCache`                         | Xóa query khi hết `cacheTime` |

| Feature                | TanStack Query            | MFEStack Query                                                  |
| ---------------------- | ------------------------- | --------------------------------------------------------------- |
| Core engine            | Query, Mutation, Observer | Query, Mutation, Observer                                       |
| Retry & pause/resume   | ✅ Built-in Retryer        | ✅ Custom Retryer class                                          |
| Cache persistence      | Plugin (experimental)     | ✅ Built-in persistPlugin                                        |
| Multi-tab sync         | BroadcastChannel          | ✅ broadcastPlugin                                               |
| Hydration SSR          | dehydrate/hydrate         | ✅ hydrate/dehydrate modules                                     |
| Plugin lifecycle hooks | Limited                   | ✅ Full plugin lifecycle (init, hydrate, dehydrate, cacheUpdate) |
| Event managers         | Focus/Online              | ✅ Focus, Online, Notify, Batch                                  |
| Adapter-agnostic       | React/Vue/Svelte          | ✅ Framework-agnostic provider layer                             |
