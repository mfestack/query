## 🧱 **Internal Plugin Orchestration Layer (Plugin Lifecycle & Priority Scheduling)**

### 1. **Mục tiêu**

Hệ thống **Plugin Orchestration Layer** trong MFEStack Core chịu trách nhiệm điều phối các plugin đã được đăng ký (persistence, broadcast, devtools, logger, sync…) theo cơ chế có thứ tự, ưu tiên và an toàn.

Cấu trúc này giúp:

* Cho phép **nhiều plugin cùng can thiệp** vào cùng một event mà không xung đột.
* Duy trì **thứ tự thực thi dựa trên priority level**.
* Cung cấp **một pipeline thống nhất** để quản lý toàn bộ lifecycle của plugin (init → update → teardown).

---

### 2. **Kiến trúc tổng quan**

```
core/
├─ plugins/
│  ├─ PluginRegistry.ts      # Lưu trữ & quản lý plugin lifecycle
│  ├─ PluginScheduler.ts     # Quản lý priority & event dispatch order
│  ├─ PluginContext.ts       # Context chia sẻ state & dependency giữa plugin
│  └─ index.ts               # Entry point export
```

### 3. **Plugin Lifecycle Overview**

Mỗi plugin trong MFEStack Core có vòng đời 5 giai đoạn chính:

| Stage                  | Event                    | Description                                                  |
| ---------------------- | ------------------------ | ------------------------------------------------------------ |
| **1. Registration**    | `register(plugin)`       | Đăng ký plugin vào registry, xác định priority.              |
| **2. Initialization**  | `onInit(client)`         | Plugin khởi tạo tài nguyên cần thiết (connection, storage…). |
| **3. Activation**      | `onEvent(type, payload)` | Lắng nghe hoặc phản ứng với event nội bộ từ core.            |
| **4. Synchronization** | `onPersist`, `onSync`    | Đồng bộ cache hoặc dữ liệu state với các adapter khác.       |
| **5. Destruction**     | `onDestroy()`            | Hủy tài nguyên khi QueryClient bị dispose.                   |

---

### 4. **Plugin Registry**

`PluginRegistry` là trung tâm lưu trữ và quản lý tất cả plugin trong hệ thống.

#### Cấu trúc:

```ts
export class PluginRegistry {
  private plugins: RegisteredPlugin[] = [];

  register(plugin: RegisteredPlugin) {
    this.plugins.push(plugin);
    this.plugins.sort((a, b) => b.priority - a.priority);
  }

  getAll() {
    return this.plugins;
  }

  dispatchEvent(event: PluginEvent) {
    for (const p of this.plugins) {
      if (p.enabled && p.onEvent) p.onEvent(event);
    }
  }

  teardown() {
    this.plugins.forEach(p => p.onDestroy?.());
  }
}
```

#### Mỗi plugin được đăng ký kèm metadata:

```ts
interface RegisteredPlugin extends AppStackPlugin {
  priority: number;   // 0–1000 (cao hơn → chạy trước)
  enabled: boolean;
}
```

### 5. **Plugin Scheduler**

`PluginScheduler` đảm bảo **thứ tự xử lý hợp lý** giữa các plugin theo từng loại event.

Ví dụ:

* `devtoolsPlugin` nên chạy **sau khi persistPlugin** để hiển thị state cuối cùng.
* `loggerPlugin` nên chạy **đầu tiên** để log toàn bộ event raw.

#### Scheduler pipeline:

```ts
export class PluginScheduler {
  constructor(private registry: PluginRegistry) {}

  run(event: PluginEvent) {
    const ordered = this.registry.getAll().sort((a, b) => b.priority - a.priority);

    for (const plugin of ordered) {
      try {
        plugin.onEvent?.(event);
      } catch (err) {
        console.error(`[MFEStack Plugin Error] ${plugin.name}:`, err);
      }
    }
  }
}
```

### 6. **Event Routing Model**

MFEStack sử dụng cơ chế **Event Routing Bus** nội bộ cho plugin communication.

#### Các nhóm event chính:

| Event Type              | Triggered By               | Purpose                          |
| ----------------------- | -------------------------- | -------------------------------- |
| `query.updated`         | QueryCache / QueryObserver | Notify state change.             |
| `mutation.updated`      | MutationObserver           | Notify mutation result.          |
| `client.persist`        | PersistManager             | Trigger persistence plugins.     |
| `client.hydrate`        | Hydration Layer            | Notify hydration-complete event. |
| `system.network.change` | OnlineManager              | Sync status across plugins.      |
| `system.focus.change`   | FocusManager               | Trigger background refetch.      |

### 7. **Priority Levels (Proposal v1)**

MFEStack định nghĩa các mức ưu tiên mặc định để tránh conflict giữa plugin:

| Priority | Plugin Type         | Description                           |
| -------- | ------------------- | ------------------------------------- |
| **1000** | `LoggerPlugin`      | Chạy đầu tiên, log toàn bộ raw event. |
| **900**  | `DevToolsPlugin`    | Theo dõi state thay đổi.              |
| **800**  | `PersistencePlugin` | Lưu/restore cache.                    |
| **700**  | `BroadcastPlugin`   | Gửi event sang app khác.              |
| **600**  | `AnalyticsPlugin`   | Theo dõi metrics, performance.        |
| **500**  | `Custom Plugins`    | Không ảnh hưởng core.                 |
| **100**  | `System Hooks`      | Internal events cuối pipeline.        |

> Các plugin custom có thể override priority khi đăng ký.

### 8. **Plugin Context System**

`PluginContext` là lớp chia sẻ state và dependency giữa các plugin cùng pipeline.
Ví dụ, `PersistPlugin` và `BroadcastPlugin` có thể cùng truy cập `QueryCache` thông qua context.

```ts
export class PluginContext {
  constructor(public client: QueryClient) {}

  getQueryCache() {
    return this.client.getQueryCache();
  }

  getOnlineManager() {
    return this.client.getOnlineManager();
  }
}
```

> ✅ Điều này giúp các plugin hoạt động *cohesively*, không cần trực tiếp truy cập vào lớp core.

---

### 9. **Error Isolation & Recovery**

Để tránh việc **một plugin lỗi làm ngừng toàn bộ pipeline**, MFEStack dùng chiến lược **try/catch isolation** cho từng plugin event.

Cơ chế:

* Mỗi plugin được bọc trong `safeInvoke()` wrapper.
* Nếu một plugin throw lỗi → log cảnh báo, **không ảnh hưởng đến plugin kế tiếp**.
* Có thể gắn cờ `critical: true` để dừng pipeline nếu lỗi nghiêm trọng (ví dụ: persist failure).

### 10. **Plugin Pipeline Example**

```
Event: query.updated
↓
[LoggerPlugin] log raw event
↓
[DevToolsPlugin] update inspector panel
↓
[PersistencePlugin] persist cache snapshot
↓
[BroadcastPlugin] notify other apps
↓
[AnalyticsPlugin] send metrics
↓
(System) notify subscribers
```

Mỗi bước hoạt động độc lập, nhưng vẫn được kiểm soát theo **thứ tự và priority**.

---

### 11. **Extending the Scheduler**

Developers có thể tự override pipeline:

```ts
queryClient.plugins.override({
  event: 'query.updated',
  before: ['logger'],
  after: ['persist'],
  handler: (ctx, event) => {
    // Custom metrics logic
  },
});
```

### 12. **Kết luận**

Hệ thống **Internal Plugin Orchestration Layer** giúp MFEStack:

* Vận hành nhiều plugin đồng thời mà không xung đột.
* Giữ vững thứ tự thực thi logic qua **priority scheduling**.
* Cho phép mở rộng và thay thế dễ dàng.
* Đảm bảo an toàn, cách ly lỗi và dễ debug.
