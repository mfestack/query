# 🧩 Testing & Debugging Strategy

### MFEStack Query Core — Internal Testing & Debugging Philosophy

MFEStack Query Core được thiết kế với triết lý **deterministic behavior** và **composable lifecycle**, do đó mọi hành vi của query, mutation, và cache đều có thể được kiểm thử độc lập. Hệ thống test hướng tới khả năng **mô phỏng (simulation)** toàn bộ vòng đời query — từ fetch, invalidate, refetch đến persist.

---

## 1. Testing Pyramid Overview

| Layer                              | Scope                                                     | Tooling                      | Example Target                               |
| ---------------------------------- | --------------------------------------------------------- | ---------------------------- | -------------------------------------------- |
| 🧱 **Unit Tests**                  | Module-level (e.g., `QueryCache`, `Retryer`, `Scheduler`) | Vitest / Jest                | validate retry backoff, cache eviction logic |
| ⚙️ **Integration Tests**           | End-to-end Core Modules                                   | Vitest + FakeNetworkAdapter  | ensure query-client + observer work together |
| 🌐 **Adapter Tests**               | Framework-level Integration (React/Vue/Svelte)            | Playwright / Testing Library | verify state sync with UI hooks              |
| 🧩 **Plugin Tests**                | Custom plugin contracts                                   | Vitest + Mock Core           | check lifecycle events, plugin hooks         |
| 🧪 **Regression & Snapshot Tests** | Cache states & hydration results                          | Jest snapshot                | ensure deterministic cache serialization     |

---

## 2. Unit Testing the Core

Mỗi module trong `/core/src` đều được kiểm thử qua các bộ test độc lập:

* **QueryCache.test.ts** → kiểm tra add/remove/invalidate query
* **MutationCache.test.ts** → kiểm tra retry, onSuccess/onError/onSettled
* **Retryer.test.ts** → mô phỏng exponential backoff và abort signal
* **Scheduler.test.ts** → validate polling interval, pause/resume logic
* **EventBus.test.ts** → đảm bảo event order và deduplication

Tất cả test sử dụng **mock clock** để đảm bảo hành vi chính xác theo thời gian (thông qua `vi.useFakeTimers()`).

---

## 3. Integration Testing

MFEStack cung cấp `createTestClient()` — một helper mô phỏng toàn bộ vòng đời query mà không cần adapter UI.
Ví dụ:

```ts
import { createTestClient } from '@mfestack/core/testing'

const client = createTestClient({
  defaultOptions: { queries: { retry: 1 } },
})

client.prefetchQuery(['todos'], fetchTodos)

await client.waitForQuery(['todos'])
expect(client.getQueryData(['todos'])).toHaveLength(3)
```

Điều này giúp kiểm thử logic fetch/cache/invalidate mà không cần môi trường trình duyệt.

---

## 4. Adapter Testing

Với từng adapter (React, Vue, Svelte...), MFEStack cung cấp test harness:

* React: `renderHook(() => useQuery(...))`
* Vue: `mount(UseQueryComponent)`
* Svelte: `render(AppStackQueryComponent)`

Tất cả adapters chia sẻ cùng `TestQueryClientProvider`, đảm bảo cache và lifecycle đồng bộ như production.

Ví dụ React:

```tsx
const { result } = renderHook(() => useQuery(['user'], fetchUser), {
  wrapper: TestQueryClientProvider,
})
await waitFor(() => expect(result.current.data).toBeDefined())
```

---

## 5. Plugin Testing

Plugins có thể được kiểm thử bằng cách inject mock hooks vào core runtime:

```ts
registerPlugin('logger', {
  onQueryStart: jest.fn(),
  onQuerySuccess: jest.fn(),
})
```

Test đảm bảo plugin nhận đúng sự kiện với thứ tự chính xác:

```ts
expect(plugin.onQueryStart).toHaveBeenCalledBefore(plugin.onQuerySuccess)
```

---

## 6. Debugging Tools

MFEStack Core cung cấp hệ thống debug nội bộ giúp dễ dàng theo dõi vòng đời query:

* **`setLogger()`** → ghi lại mọi event (query start, success, invalidate)
* **`enableDebugMode()`** → bật event tracing (console + timeline)
* **`dumpQueryCache()`** → export toàn bộ cache snapshot ra JSON
* **`devtools` Plugin** → visual timeline cho query và mutation

Ví dụ:

```ts
setLogger({
  log: console.log,
  warn: console.warn,
  error: console.error,
})
```

---

## 7. Snapshot & Regression Testing

Mọi cache state và hydration output đều có thể snapshot để đảm bảo **deterministic serialization**:

```ts
expect(client.dehydrate()).toMatchSnapshot()
```

MFEStack đảm bảo mọi object trong cache đều **structurally shared** (replaceEqualDeep), giúp snapshot ổn định ngay cả khi refetch nhiều lần.

---

## 8. Testing Philosophy Summary

✅ Deterministic state machine — dễ kiểm thử và tái lập
✅ No hidden side effects — mọi thay đổi đi qua event bus
✅ Unified test client — mô phỏng cache, query, mutation
✅ Reproducible timeline — có thể tua tiến/lùi vòng đời query

---

**Kết luận:**
MFEStack Core được xây dựng theo hướng **testable-first architecture**, nghĩa là mọi hành vi (query, cache, plugin, adapter) đều có thể được mô phỏng độc lập. Môi trường test thống nhất giúp việc mở rộng và refactor thư viện trở nên an toàn, ổn định và minh bạch.
