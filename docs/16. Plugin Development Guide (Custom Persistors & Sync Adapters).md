## 🧩 **Plugin Development Guide (Custom Persistors & Sync Adapters)**

### 1. **Tổng quan**

MFEStack Query Core được thiết kế với **Plugin-First Architecture**, cho phép nhà phát triển mở rộng hệ thống mà không cần can thiệp vào mã nguồn lõi.
Plugin có thể được dùng để:

* Mở rộng **Persistence Layer** (custom storage hoặc sync).
* Bổ sung **Monitoring**, **Logging**, hoặc **Analytics hooks**.
* Tạo **cross-environment adapters** (Node, Browser, Edge, Native).

---

### 2. **Cấu trúc tổng thể Plugin**

```
plugins/
├─ persist/
│  ├─ storage/
│  │  ├─ customPersistor.ts
│  │  └─ customStorageAdapter.ts
│  └─ sync/
│     ├─ customSyncAdapter.ts
│     └─ broadcastSync.ts
└─ index.ts
```

Mỗi plugin thường bao gồm:

* **Plugin Factory**: Hàm khởi tạo plugin và đăng ký vào hệ thống.
* **Adapter Interface**: Xác định các phương thức cần cài đặt.
* **Plugin Manifest**: Thông tin meta (name, version, hooks, lifecycle).
* **Lifecycle hooks**: Các điểm mở rộng mà plugin có thể can thiệp vào Core.

---

### 3. **Plugin Interface**

#### 🧱 `AppStackPlugin` (Base Interface)

```ts
export interface AppStackPlugin {
  name: string;
  version: string;
  onInit?(client: QueryClient): void;
  onDestroy?(): void;
  onQueryUpdate?(query: Query): void;
  onMutationUpdate?(mutation: Mutation): void;
  onPersist?(): Promise<void>;
}
```

> 🔹 Tất cả plugin (persistors, sync adapters, logger, metrics, v.v.) đều tuân theo interface này.
> Core sẽ tự động gọi các hook khi có sự kiện tương ứng.

### 4. **Custom Persistor Development**

#### 📦 Mục tiêu

Tạo custom persistor để lưu dữ liệu QueryClient sang một backend hoặc storage khác (Redis, S3, KV store…).

#### 🔧 Cấu trúc cơ bản

```ts
import { Persistor, PersistedClient } from '@mfestack/core/plugins/persist';

export class RedisPersistor implements Persistor {
  constructor(private redisClient: RedisClient, private key = 'mfestack-cache') {}

  async persistClient(client: QueryClient) {
    const data = dehydrate(client);
    await this.redisClient.set(this.key, JSON.stringify(data));
  }

  async restoreClient(): Promise<PersistedClient | undefined> {
    const json = await this.redisClient.get(this.key);
    return json ? JSON.parse(json) : undefined;
  }

  async removeClient() {
    await this.redisClient.del(this.key);
  }
}
```

#### 🧭 Đăng ký plugin vào hệ thống

```ts
import { persistQueryClient } from '@mfestack/core/plugins/persist';

persistQueryClient({
  queryClient,
  persistor: new RedisPersistor(redisClient),
  dehydrateOptions: { shouldDehydrateMutation: true },
});
```

### 5. **Custom Sync Adapter Development**

#### 🎯 Mục tiêu

Tạo adapter để đồng bộ cache giữa nhiều instance hoặc ứng dụng thông qua cơ chế riêng (WebSocket, MQTT, gRPC…).

#### 🧩 Interface

```ts
export interface SyncAdapter {
  connect(): void;
  broadcast(event: SyncEvent): void;
  onMessage(callback: (event: SyncEvent) => void): void;
  disconnect(): void;
}

export interface SyncEvent {
  type: 'invalidate' | 'refetch' | 'hydrate';
  payload?: any;
}
```

#### 🌐 Ví dụ: WebSocket Sync Adapter

```ts
import { SyncAdapter } from '@mfestack/core/plugins/persist/sync';

export class WebSocketSyncAdapter implements SyncAdapter {
  private ws: WebSocket;

  constructor(private url: string, private client: QueryClient) {
    this.ws = new WebSocket(url);
  }

  connect() {
    this.ws.onmessage = (msg) => {
      const event = JSON.parse(msg.data);
      this.handleEvent(event);
    };
  }

  broadcast(event: SyncEvent) {
    this.ws.send(JSON.stringify(event));
  }

  handleEvent(event: SyncEvent) {
    if (event.type === 'invalidate') {
      this.client.invalidateQueries(event.payload);
    } else if (event.type === 'hydrate') {
      hydrate(this.client, event.payload);
    }
  }

  disconnect() {
    this.ws.close();
  }
}
```

### 6. **Plugin Lifecycle & Registration**

Plugin có thể được đăng ký toàn cục hoặc theo từng `QueryClient`.

#### 🔄 Đăng ký qua API

```ts
const queryClient = new QueryClient({
  plugins: [new RedisPersistor(redisClient), new WebSocketSyncAdapter(url, client)],
});
```

#### ⚙️ Hook event lifecycle

Core sẽ kích hoạt các hook như sau:

| Lifecycle Event    | Trigger                  | Plugin Hook          |
| ------------------ | ------------------------ | -------------------- |
| `client.init`      | Khi QueryClient khởi tạo | `onInit()`           |
| `query.updated`    | Query thay đổi           | `onQueryUpdate()`    |
| `mutation.updated` | Mutation hoàn tất        | `onMutationUpdate()` |
| `persist.run`      | Khi cache được lưu       | `onPersist()`        |
| `client.destroy`   | Khi client bị dispose    | `onDestroy()`        |

### 7. **Best Practices cho Plugin Developer**

| Mục tiêu                | Khuyến nghị                                           |
| ----------------------- | ----------------------------------------------------- |
| 🔒 Bảo mật              | Mã hoá dữ liệu lưu trữ (AES/GCM, RSA).                |
| 🧠 Tránh race condition | Dùng debounce/throttle khi broadcast/persist.         |
| 🧩 Tái sử dụng code     | Tạo adapter base class kế thừa `BaseSyncAdapter`.     |
| 🚀 Hiệu năng            | Sử dụng incremental persist thay vì full snapshot.    |
| ⚙️ Phát triển mở rộng   | Định nghĩa plugin manifest (metadata, version, deps). |
| 🧾 Kiểm thử             | Dùng Mock QueryClient để test plugin độc lập.         |

```json
{
  "name": "@mfestack/plugin-redis-sync",
  "version": "1.0.0",
  "type": "sync",
  "description": "Synchronize queries via Redis pub/sub channels",
  "mfestack": {
    "apiVersion": "v1",
    "compatibility": ">=1.0.0",
    "hooks": ["onInit", "onPersist", "onDestroy"]
  }
}
```

### 9. **Tương thích với các Framework Adapter**

Các plugin hoạt động xuyên suốt giữa các adapter:

* ✅ React → `useQuery` tự động trigger persist/sync.
* ✅ Vue → Reactive watcher subscribe vào event bus.
* ✅ Angular → Service layer sử dụng Zone-safe subscription.

### 🔚 **Tóm tắt**

Hệ thống plugin của MFEStack Query Core cung cấp **một khung mở rộng mô-đun mạnh mẽ**, nơi mọi thành phần (storage, sync, analytics, monitor) đều có thể được **thêm, thay thế hoặc tuỳ biến** mà không ảnh hưởng đến Core.
Nhờ đó, MFEStack có thể phục vụ từ các ứng dụng đơn giản (SPA) đến môi trường phức tạp (multi-app, offline-first, distributed UI).
