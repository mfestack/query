# 📘 MFEStack Core: Internal Architecture & Module Responsibilities

## 1. Architectural Overview

MFEStack Query Core được thiết kế với kiến trúc **layered và composable**, tối ưu cho khả năng mở rộng và khả năng tích hợp với các framework khác nhau (React, Vue, Svelte, Solid,…).
Mỗi layer trong core phục vụ một vai trò cụ thể trong pipeline quản lý dữ liệu:

```
┌──────────────────────────────┐
│       QueryClient Layer      │  ← Entry point / public API
├──────────────────────────────┤
│      Query & Mutation Layer  │  ← State machine for async data
├──────────────────────────────┤
│      Cache & Manager Layer   │  ← Lifecycle & synchronization
├──────────────────────────────┤
│   Hydration & Plugin System  │  ← SSR, persistence, cross-app sync
├──────────────────────────────┤
│            Utils Layer       │  ← Shared utilities & abstractions
└──────────────────────────────┘
```

---

## 2. Client Layer

### 🔹 `QueryClient`

* **Vai trò:** Entry point chính, điều phối toàn bộ vòng đời query và mutation.
* **Trách nhiệm:**

  * Khởi tạo `QueryCache` và `MutationCache`
  * Quản lý context cho observer subscriptions
  * Xử lý global defaults (retry, staleTime, refetchInterval,…)
  * Giao tiếp với `NotifyManager` để batching event
* **Đặc điểm nổi bật:**

  * Cho phép inject custom `logger`, `retryer`, `plugins`
  * Thread-safe cho môi trường đa app hoặc đa tab

### 🔹 `createQueryClient`

* **Vai trò:** Factory method để tạo `QueryClient` instance.
* **Trách nhiệm:** Hợp nhất `defaultOptions` và các plugin được khai báo trong config.

### 🔹 `QueryClientProvider`

* **Vai trò:** Provider cho adapter layer (React/Vue/Solid,…)
* **Trách nhiệm:** Cung cấp context cho các component hooks (`useQuery`, `useMutation`,…)

---

## 3. Query System

### 🔹 `Query`

* **Vai trò:** Đối tượng mô tả 1 “fetch unit” duy nhất.
* **Trạng thái quản lý:** `idle`, `loading`, `success`, `error`
* **Trách nhiệm:**

  * Lưu trữ data, error, timestamps
  * Quản lý observers (client subscriptions)
  * Thực hiện structural sharing để tránh render thừa

### 🔹 `QueryCache`

* **Vai trò:** Cấu trúc dữ liệu trung tâm lưu trữ và tìm kiếm tất cả queries đang hoạt động.
* **Trách nhiệm:**

  * Hash queryKey → Query instance
  * Cung cấp API: `find()`, `findAll()`, `remove()`
  * Dọn dẹp GC theo `cacheTime`

### 🔹 `QueryObserver`

* **Vai trò:** Lớp theo dõi thay đổi của một Query cụ thể.
* **Trách nhiệm:**

  * Lắng nghe thay đổi state (data/error/fetching)
  * Gửi notification qua `NotifyManager`
  * Được dùng bởi adapter hooks (`useQuery`, `watchQuery`)

### 🔹 `QueryManager`

* **Vai trò:** Quản lý state transitions và refetch lifecycle.
* **Trách nhiệm:**

  * Trigger `fetch()` hoặc `invalidate()`
  * Áp dụng policy (staleTime, refetchOnFocus,…)
  * Phối hợp với `Retryer` và `CancelController`

---

## 4. Mutation System

### 🔹 `Mutation`

* **Vai trò:** Mô hình hóa một thao tác ghi dữ liệu (POST, PUT, DELETE,…)
* **Trạng thái:** `idle`, `loading`, `success`, `error`
* **Trách nhiệm:**

  * Quản lý optimistic updates
  * Kích hoạt rollback khi lỗi
  * Xử lý retry logic qua `Retryer`

### 🔹 `MutationCache`

* **Vai trò:** Lưu trữ tất cả mutation đang chạy.
* **Trách nhiệm:**

  * Cung cấp API: `add`, `remove`, `findAll`
  * Dọn dẹp mutation sau khi hoàn tất hoặc timeout
  * Kích hoạt persistence plugin khi có

### 🔹 `MutationObserver`

* **Vai trò:** Theo dõi kết quả mutation theo context client.
* **Trách nhiệm:** Trigger re-render hoặc side effects (VD: toast, UI feedback)

## 5. Manager Layer

| Manager           | Vai trò                    | Mô tả                                          |
| ----------------- | -------------------------- | ---------------------------------------------- |
| **FocusManager**  | Theo dõi trạng thái cửa sổ | Tự động refetch khi tab được focus trở lại     |
| **OnlineManager** | Theo dõi kết nối mạng      | Trì hoãn fetch khi offline, resume khi online  |
| **NotifyManager** | Gom event notification     | Giảm tần suất re-render bằng batching          |
| **BatchManager**  | Gom các state update       | Tối ưu performance cho UI framework            |
| **Retryer**       | Quản lý retry logic        | Hỗ trợ delay, exponential backoff, cancelation |

---

## 6. Hydration Layer

| File                  | Vai trò                                    |
| --------------------- | ------------------------------------------ |
| **dehydrate.ts**      | Serialize query/mutation cache khi SSR     |
| **hydrate.ts**        | Rehydrate lại cache ở client-side          |
| **hydrationUtils.ts** | Xử lý logic merge, timestamp, stale checks |

MFEStack hỗ trợ SSR hoàn chỉnh, tương tự TanStack Query — có thể persist và khôi phục cache giữa server & client.

---

## 7. Plugin Layer

MFEStack định nghĩa plugin theo interface thống nhất:

```ts
interface AppStackPlugin {
  name: string;
  onInit?(client: QueryClient): void;
  onCacheUpdate?(cache: QueryCache): void;
  onHydrate?(data: any): void;
  onDehydrate?(): any;
}
```

| Plugin              | Chức năng chính                                |
| ------------------- | ---------------------------------------------- |
| **persistPlugin**   | Lưu cache vào LocalStorage / IndexedDB         |
| **broadcastPlugin** | Đồng bộ cache giữa các tab/browser             |
| **devtoolsPlugin**  | Giao diện debug cho DevTools                   |
| **loggerPlugin**    | Log event lifecycle (fetch, retry, invalidate) |

Plugins được đăng ký qua `client.use(plugin)` và có thể mở rộng module tùy chỉnh.

## 8. Utils Layer

* **hash.ts** – Sinh key hash ổn định cho query
* **stableStringify.ts** – Serialize object có thứ tự
* **replaceEqualDeep.ts** – Thực hiện structural sharing (deep compare)
* **scheduler.ts** – Điều phối background refetch
* **cancelController.ts** – Cung cấp khả năng huỷ request
* **helpers.ts** – Các tiện ích chung (timestamp, deep merge,…)
* **isServer.ts** – Xác định môi trường SSR/CSR

---

## 10. Summary

MFEStack Core là nền tảng composable cho **asynchronous data orchestration**, tương đương TanStack Query về scope, nhưng hướng đến:

* Modular plugin-based architecture
* SSR hydration & persistence out-of-the-box
* Multi-app cache synchronization
* Framework-agnostic adapters
