### 🕓 Scheduler & Background Task Management

MFEStack Core’s **Scheduler subsystem** is responsible for coordinating all background activities — query refetches, stale checks, mutation retries, and cache garbage collection — without blocking the main execution thread or introducing race conditions.

---

### 1. **Overview**

The Scheduler manages task queues for:

* **Query refetch intervals**
* **Garbage collection timers**
* **Retry attempts (with exponential backoff)**
* **Batch processing (deferred state updates)**
  It ensures predictable execution timing through a unified scheduling mechanism that decouples background logic from UI layers.

---

### 2. **Core Components**

| Component           | Responsibility                                                                                                  |
| ------------------- | --------------------------------------------------------------------------------------------------------------- |
| `TaskScheduler`     | Manages task lifecycle (enqueue, run, cancel).                                                                  |
| `TaskQueue`         | Holds scheduled jobs with their execution timestamps.                                                           |
| `BackoffController` | Calculates retry intervals using exponential or custom backoff strategies.                                      |
| `IdleTaskRunner`    | Executes non-critical tasks when the main thread is idle (using `requestIdleCallback` or equivalent polyfills). |
| `TickLoop`          | Central loop that drives scheduled task execution; ticked via microtasks or postMessage.                        |

---

### 3. **Execution Model**

The Scheduler operates with two layers of granularity:

* **Microtasks:** Immediate callbacks (Promise-based) used for observer notifications and atomic cache updates.
* **Macrotasks:** Delayed or interval-based operations for refetching, retries, or GC cleanup.

```ts
scheduler.enqueue('refetch', () => queryClient.refetchQueries(), {
  delay: 10000, // 10s interval
  repeat: true,
});
```

Tasks are stored in a priority queue sorted by `nextExecutionTime`. The `TickLoop` continuously checks and dispatches due tasks.

---

### 4. **Task Types**

| Task Type | Description                                               | Trigger                 |
| --------- | --------------------------------------------------------- | ----------------------- |
| `refetch` | Periodically fetches queries marked as `refetchInterval`. | Timer-based             |
| `retry`   | Retries failed mutations/queries with exponential delay.  | Error handler           |
| `gc`      | Purges stale queries from the cache after TTL expiration. | Scheduler cycle         |
| `batch`   | Aggregates UI updates and notifies observers in batches.  | Batched observer system |

---

### 5. **Backoff & Retry Logic**

The **Retryer** integrates with the Scheduler to handle network instability:

```ts
retryer.scheduleRetry({
  attempt: 3,
  maxAttempts: 5,
  baseDelay: 500,
  factor: 2, // exponential
});
```

Retries are registered as delayed tasks and automatically cancelled when queries resolve successfully or when network state changes (`OnlineManager`).

---

### 6. **Idle-Time Optimization**

When available, the Scheduler leverages **`requestIdleCallback`** to execute non-critical cleanup and persistence tasks during idle frames, minimizing main-thread interference.

If not available, a fallback mechanism uses `setTimeout` with adaptive delays based on recent system load.

---

### 7. **BatchManager Integration**

The **BatchManager** hooks into the Scheduler via shared event channels:

* Collects multiple state updates per tick.
* Flushes updates at the next microtask or after a fixed `batchInterval`.
* Reduces observer churn and re-render frequency.

---

### 8. **Custom Scheduling Hooks**

Plugins can register background tasks:

```ts
pluginSystem.registerTask('sync', {
  handler: syncRemoteCache,
  interval: 60000, // run every 60s
  priority: 'low',
});
```

Tasks can define:

* `priority` (`high` | `normal` | `low`)
* `interval` (ms)
* `repeat` (boolean)
* `abortSignal` (optional cancellation)

---

### 9. **Thread Safety & Concurrency**

All operations within the Scheduler are guarded by:

* **Mutex-based task locks** (to prevent concurrent writes)
* **Atomic state transitions** (to ensure deterministic timing)
* **Cancellation tokens** (to abort tasks upon context change)

---

### 10. **Summary**

The Scheduler system provides:
✅ Unified, non-blocking execution of all timed or deferred logic
✅ Predictable retries, garbage collection, and refetch timing
✅ Low-overhead batching and idle-time optimization
✅ Extensible scheduling interface for custom plugin tasks

Together, it forms the **temporal backbone** of MFEStack Core — ensuring that data freshness, retry logic, and cache hygiene operate seamlessly and efficiently in the background.
