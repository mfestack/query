# 🔄 Garbage Collection & Memory Reclamation

**Module:** `QueryCache`, `MutationCache`, `NotifyManager`
**Related Components:** `QueryClient`, `BatchManager`, `Retryer`

---

## 1️⃣ Overview

Garbage Collection (GC) trong **MFEStack Query Core** chịu trách nhiệm dọn dẹp các query và mutation không còn được tham chiếu (orphaned), đã stale quá lâu hoặc không được observer nào quan tâm.
Cơ chế này đảm bảo bộ nhớ tối ưu, tránh memory leak và giữ cho cache luôn “fresh but lean”.

MFEStack áp dụng **reference-based retention model**, tương tự như TanStack Query, nhưng mở rộng thêm **priority cleanup tiers** và **batch-safe invalidation** cho môi trường multi-client.

---

## 2️⃣ Core Lifecycle Phases

### 🧩 2.1 Query Retention

Mỗi `Query` trong `QueryCache` có 3 trạng thái giữ lại (retention states):

| State               | Description                                    | Cleanup Condition           |
| ------------------- | ---------------------------------------------- | --------------------------- |
| **Active**          | Có ít nhất 1 `QueryObserver` đang subscribe    | Không dọn                   |
| **Inactive (Idle)** | Không có observer, nhưng còn trong `cacheTime` | Dọn sau `cacheTime` hết hạn |
| **Garbage**         | Hết `cacheTime` và không còn reference         | Xóa hoàn toàn khỏi cache    |

`cacheTime` được định nghĩa trong `defaultOptions` (mặc định 5 phút).

---

### 🧩 2.2 Mutation Retention

Mutation sử dụng cơ chế tương tự query, nhưng có thêm `retryBackoffTime` và `retryLimit` để trì hoãn dọn dẹp khi mutation đang retry.

| State        | Condition                                         |
| ------------ | ------------------------------------------------- |
| **Pending**  | Đang thực hiện → giữ lại trong memory             |
| **Retrying** | Giữ lại cho đến khi retry hoàn tất hoặc hết limit |
| **Settled**  | Dọn sau khi mutation được xử lý & notify hoàn tất |

## 3️⃣ Garbage Collection Flow

1. **Trigger:**

   * `QueryObserver.unsubscribe()`
   * `BatchManager.flush()`
   * `OnlineManager`/`FocusManager` event (resume activity)

2. **Mark phase:**

   * Đánh dấu tất cả query/mutation không có reference (no active observer).

3. **Sweep phase:**

   * `NotifyManager` thực hiện cleanup định kỳ.
   * Mỗi vòng lặp, cache sẽ xóa các item vượt quá `cacheTime` (hoặc theo plugin persistence policy).

4. **Plugin hook:**

   * Plugin như `persistPlugin` có thể override hành vi GC (`onGarbageCollect`, `onQueryRemove`).

## 4️⃣ Advanced Memory Reclamation Features

### 🧠 Reference Counting

Mỗi `Query` duy trì bộ đếm `observerCount`. Khi giảm về 0, bắt đầu đếm ngược `cacheTime`.
Nếu trong thời gian đó có observer mới, đếm ngược được reset.

### 🧩 Deferred Cleanup

GC không xóa query ngay lập tức mà đẩy vào hàng đợi (queue) trong `NotifyManager`, sau đó cleanup theo batch — giúp giảm chi phí GC trong ứng dụng lớn.

### 🔁 Smart Retention Tiering

MFEStack hỗ trợ **multi-tier cache**:

* Tier 1: Active Queries (RAM)
* Tier 2: Warm Queries (short-term memory)
* Tier 3: Persisted Queries (storage plugin như IndexedDB)

Điều này cho phép cân bằng giữa tốc độ truy cập và dung lượng lưu trữ.

---

## 5️⃣ Integration with Retry & Refetch

Khi mutation hoặc query đang retry/refetch, MFEStack **suspend cleanup** để tránh mất dữ liệu giữa chừng.
`Retryer` báo hiệu `NotifyManager` tạm dừng GC cho đến khi mutation kết thúc hoặc fail hoàn toàn.

---

## 6️⃣ Extensibility Hooks

MFEStack mở ra các event lifecycle hooks cho developer tùy biến:

| Hook                                | Description                                      |
| ----------------------------------- | ------------------------------------------------ |
| `onGarbageCollect(query)`           | Kích hoạt khi query bị GC                        |
| `onCacheEvict(key, reason)`         | Khi item bị xóa khỏi cache                       |
| `onRetainStateChange(query, state)` | Khi query chuyển trạng thái active/inactive      |
| `onMemoryPressure(level)`           | Phát tín hiệu cho plugin khi hệ thống low-memory |

## ✅ Summary

MFEStack Query Core cung cấp một hệ thống GC thông minh hơn TanStack Query nhờ:

* Batching cleanup để tránh chặn main thread
* Multi-tier retention giúp mở rộng cho mobile/offline apps
* Plugin hook cho phép theo dõi & ghi log cleanup lifecycle

Cơ chế này đảm bảo **cache luôn sạch, hiệu năng cao, và dễ mở rộng** cho mọi framework adapter (React, Vue, Solid, Svelte…).
