## 📦 Persistence, Broadcast, and Multi-App Synchronization Layer

### 1. Overview

**MFEStack Query Core** coi *state continuity* là trụ cột cốt lõi:

> “Data should persist, sync, and rehydrate seamlessly — across sessions, tabs, and even apps.”

Lớp này được triển khai thông qua ba plugin chính:

* **PersistPlugin** → lưu/khôi phục state
* **BroadcastPlugin** → đồng bộ state giữa các instance (multi-tab hoặc multi-app)
* **SyncCoordinator** → tầng quản lý trung gian đảm bảo tính toàn vẹn dữ liệu khi đồng bộ

Mục tiêu là đạt tính năng tương đương (và vượt qua) TanStack Query về persistence và synchronization, nhưng tách hoàn toàn khỏi core logic để dễ mở rộng.

---

### 2. Persistence Layer

#### 2.1. Design Principles

* **Storage Agnostic:** không phụ thuộc vào storage cụ thể (`localStorage`, `IndexedDB`, `AsyncStorage`, `Redis`, …).
* **Partial Persistence:** cho phép chỉ lưu một phần của cache (e.g. exclude ephemeral queries).
* **Versioned Snapshots:** đảm bảo khả năng tương thích backward khi schema thay đổi.
* **Auto-expire Mechanism:** query hết hạn không được restore lại.

#### 2.2. Core Entities

```ts
export interface PersistedSnapshot {
  version: number;
  timestamp: number;
  queries: PersistedQuery[];
  mutations: PersistedMutation[];
}

export interface PersistedQuery {
  queryHash: string;
  state: QueryState;
  meta?: Record<string, any>;
}
```

#### 2.3. Persist Flow

```text
[Cache State]
   ↓
serialize()  →  JSON (or binary)
   ↓
storage.setItem('mfestack-cache', snapshot)
```

* Khi client idle hoặc tab inBackground → trigger persist event.
* Plugin `PersistPlugin` thực hiện:

  1. Thu thập query/mutation state.
  2. Áp dụng filter & serializer.
  3. Lưu xuống storage với version header.

#### 2.4. Rehydrate Flow

```text
[Startup]
   ↓
storage.getItem('mfestack-cache')
   ↓
validateVersion() → mergeToCache()
   ↓
notifyObservers()
```

* Khi khởi động app, client tự động load snapshot (nếu hợp lệ).
* Quá trình rehydrate diễn ra **asynchronously** để không block render.
* Queries expired → bỏ qua, giữ lại data fresh.

### 3. Broadcast Layer

#### 3.1. Purpose

Cho phép **nhiều instance của QueryClient (tab, iframe, hoặc app riêng)** chia sẻ cache chung theo thời gian thực.

Ví dụ: người dùng mở hai tab ứng dụng — tab A fetch dữ liệu, tab B tự động cập nhật mà không cần gọi lại API.

#### 3.2. Implementation

```ts
export interface BroadcastMessage {
  type: 'query-updated' | 'mutation-updated' | 'cache-reset';
  payload: any;
  origin: string;
  timestamp: number;
}
```

* Mặc định sử dụng `BroadcastChannel` API.
* Có thể fallback sang `LocalStorage` events hoặc `WebSocket` tùy môi trường.

#### 3.3. Sync Flow

```text
Tab A: query updated
   ↓
serialize state → postMessage(channel)
   ↓
Tab B: onMessage() → merge query state
```

Cơ chế merge theo nguyên tắc:

* Nếu queryHash giống nhau → so sánh `updatedAt`, chọn bản mới hơn.
* Nếu khác → thêm mới.

#### 3.4. Multi-App Mode

MFEStack hỗ trợ sync giữa nhiều **ứng dụng riêng biệt** (khác domain hoặc workspace) thông qua **Remote Sync Bridge**:

* Dùng WebSocket hoặc SharedWorker làm hub.
* Mỗi app gửi diff thay vì full snapshot.
* SyncCoordinator xử lý conflict resolution (theo timestamp và origin priority).

### 4. SyncCoordinator

Đây là module trung gian nằm giữa persistence và broadcast:

```text
QueryClient
   ↓
   ├── PersistPlugin
   ├── BroadcastPlugin
   └── SyncCoordinator
```

**Nhiệm vụ:**

* Điều phối thời điểm sync/persist để tránh ghi đè lẫn nhau.
* Debounce nhiều event update liên tiếp.
* Duy trì consistency giữa local cache, persisted snapshot và remote broadcast.

**Ví dụ:**

```ts
class SyncCoordinator {
  constructor(client, { debounceMs = 300 } = {}) {
    this.client = client;
    this.debounceMs = debounceMs;
  }

  handleCacheUpdate() {
    this.schedulePersist();
    this.broadcastDiff();
  }
}
```

### 5. Versioning & Conflict Resolution

MFEStack áp dụng cơ chế version header và timestamp-based merge:

| Case                            | Resolution                               |
| ------------------------------- | ---------------------------------------- |
| Snapshot version < current      | Skip rehydrate                           |
| Same queryHash, newer timestamp | Replace old                              |
| Same queryHash, equal timestamp | Merge metadata                           |
| Mutation conflict               | Merge with latest `status=success` entry |

Tính năng này giúp tránh mất dữ liệu khi multi-tab sync và rehydrate xảy ra đồng thời.

### 6. Comparison with TanStack Query

| Feature               | TanStack Query              | MFEStack Query             |
| --------------------- | --------------------------- | -------------------------- |
| Persisted Cache       | ✅ (experimental)            | ✅ (pluginized, stable)     |
| Storage Flexibility   | LocalStorage / AsyncStorage | Any (custom adapter)       |
| Versioned Persistence | ❌                           | ✅ built-in                 |
| Broadcast Sync        | ✅                           | ✅ (with extended protocol) |
| Multi-App Sync        | ❌                           | ✅ via Remote Sync Bridge   |
| Conflict Resolution   | Limited                     | ✅ Timestamp-based merge    |
| Rehydrate on Startup  | ✅                           | ✅ Async, version-aware     |
| Sync Coordinator      | ❌                           | ✅ prevents race conditions |

### 7. Future Enhancements

* **Encrypted Persistence:** hỗ trợ AES/crypto để bảo vệ snapshot sensitive data.
* **Incremental Sync:** gửi chỉ diff thay vì full snapshot để tối ưu hiệu suất.
* **Cloud Sync Service:** đồng bộ qua API trung gian (giống Firestore cache sync).
* **Offline Replay:** tự động khôi phục mutation queue sau khi online trở lại.
