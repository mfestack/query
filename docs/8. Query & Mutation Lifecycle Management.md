## 🧠 Query & Mutation Lifecycle Management

### 1. Overview

Trong **MFEStack Core**, lifecycle management là “trái tim” điều phối **data fetching, caching, retrying, synchronization và mutation flow**.
Hệ thống được xây dựng với mục tiêu:

* Đảm bảo **trạng thái nhất quán** giữa UI, cache và network.
* Giảm thiểu **fetch trùng lặp** và **re-render thừa**.
* Cung cấp **điểm hook rõ ràng** cho plugin (logging, analytics, persistence).

Kiến trúc được chia làm hai phần chính:

1. `Query Lifecycle` — xử lý dữ liệu *read* (GET).
2. `Mutation Lifecycle` — xử lý dữ liệu *write* (POST, PUT, DELETE).

---

### 2. Query Lifecycle

#### 2.1. State Machine

Mỗi `Query` có state riêng trong `Query.ts`:

```ts
type QueryStatus = 'idle' | 'loading' | 'success' | 'error'
type FetchStatus = 'idle' | 'fetching' | 'paused'

interface QueryState<TData> {
  data?: TData
  error?: unknown
  status: QueryStatus
  fetchStatus: FetchStatus
  updatedAt: number
  dataUpdatedAt: number
  fetchFailureCount: number
}
```

#### 2.2. Lifecycle Stages

| Stage       | Description                 | Trigger                                    |
| ----------- | --------------------------- | ------------------------------------------ |
| **Idle**    | Query chưa được gọi lần nào | init                                       |
| **Loading** | Fetching đang diễn ra       | `fetchQuery()`                             |
| **Success** | Dữ liệu fetch thành công    | `onSuccess`                                |
| **Error**   | Fetch thất bại, hết retry   | `onError`                                  |
| **Stale**   | Dữ liệu cũ, cần refetch     | sau `staleTime` hoặc `invalidateQueries()` |

---

#### 2.3. Flow Diagram

```text
+--------+       +----------+       +-----------+
|  Idle  | ----> | Fetching | ----> |  Success  |
|        |       |          | ----> |   Error   |
+--------+       +----------+       +-----------+
                     ↑
                     |
                  Refetch
```

---

#### 2.4. Core Lifecycle Flow

1. **Initialization**

   * Khi gọi `client.fetchQuery(key, fn)` → kiểm tra cache.
   * Nếu tồn tại query hợp lệ (chưa stale) → return cached data.
   * Nếu không → khởi tạo `Query` mới qua `QueryManager`.

2. **Fetching**

   * Gọi `fetchFn` trong `Retryer`.
   * Retryer chịu trách nhiệm retry, pause/resume, cancel.
   * Trong quá trình fetch → notify observers (`QueryObserver`).

3. **Success / Error Transition**

   * Khi fetch hoàn tất:

     * `QueryState` chuyển sang `success` hoặc `error`.
     * Dữ liệu được lưu trong cache (`QueryCache.set()`).
     * Observers được notify → UI cập nhật.

4. **Stale & Refetch**

   * Sau `staleTime`, query được đánh dấu stale.
   * Khi người dùng focus lại tab hoặc mạng khôi phục → `FocusManager` / `OnlineManager` trigger refetch.

5. **Garbage Collection**

   * Nếu không còn observer → countdown `cacheTime`.
   * Hết thời gian → query bị xóa khỏi cache.

---

#### 2.5. Retryer Flow

`Retryer.ts` điều phối retry có delay & backoff:

```ts
new Retryer({
  fn: fetchFn,
  maxRetries: 3,
  delay: (attempt) => 1000 * 2 ** attempt, // exponential
  onSuccess,
  onError,
})
```

* Có thể *pause/resume* khi offline (`OnlineManager`).
* Hỗ trợ *abort signal* để hủy fetch.
* Tích hợp với plugin để theo dõi trạng thái retry (e.g., DevTools, Logger).

---

#### 2.6. Observer Notification Model

MFEStack sử dụng **observer pattern** cho query updates:

```ts
class QueryObserver {
  onUpdate(callback) { ... }
  unsubscribe() { ... }
}
```

* Nhiều observer có thể subscribe cùng một `Query`.
* Khi query cập nhật, tất cả observers được thông báo đồng bộ qua `NotifyManager`.
* `NotifyManager` gom update để tránh render lại quá nhiều lần.

### 3. Mutation Lifecycle

#### 3.1. State Machine

```ts
type MutationStatus = 'idle' | 'loading' | 'success' | 'error'

interface MutationState<TData, TError> {
  status: MutationStatus
  data?: TData
  error?: TError
  context?: any
}
```

#### 3.2. Lifecycle Stages

| Stage       | Description        | Trigger     |
| ----------- | ------------------ | ----------- |
| **Idle**    | Mutation chưa chạy | init        |
| **Loading** | Gửi request        | `mutate()`  |
| **Success** | Thành công         | `onSuccess` |
| **Error**   | Thất bại           | `onError`   |

---

#### 3.3. Mutation Flow

```text
+--------+       +----------+       +-----------+
|  Idle  | ----> | Loading  | ----> |  Success  |
|        |       |          | ----> |   Error   |
+--------+       +----------+       +-----------+
```

1. **Triggering**

   * Khi `client.mutate({ key, fn, onSuccess, onError })` được gọi.
   * `MutationCache` tạo `Mutation` mới và track trạng thái.

2. **Execution**

   * Mutation chạy qua `Retryer` để hỗ trợ retry và cancel.
   * Các observer (`MutationObserver`) sẽ được thông báo.

3. **Post-success / Post-error**

   * `onSuccess` hoặc `onError` được gọi.
   * Nếu mutation thành công → tự động invalidate query liên quan.
   * Có thể dùng `onSettled` để chạy cleanup logic.

4. **Persistence & Sync**

   * Nếu app reload giữa mutation → trạng thái mutation vẫn lưu qua plugin persistence.
   * Khi resume → mutation tiếp tục retry nếu chưa hoàn tất.

---

#### 3.4. Mutation Retry & Backoff

Tương tự `Query`, mutation có retry logic:

```ts
client.setMutationDefaults('updateUser', {
  retry: 2,
  retryDelay: (attempt) => 500 * attempt,
});
```

* Có thể cấu hình per-mutation hoặc global.
* Dừng retry nếu lỗi “fatal” (e.g., 4xx).

---

#### 3.5. Optimistic Updates

MFEStack hỗ trợ *optimistic update* trong mutation flow:

```ts
client.mutate({
  mutationFn: updateUser,
  onMutate: (vars) => {
    const prev = client.getQueryData(['user', vars.id])
    client.setQueryData(['user', vars.id], (old) => ({ ...old, ...vars }))
    return { prev }
  },
  onError: (err, vars, context) => {
    client.setQueryData(['user', vars.id], context.prev)
  },
  onSuccess: () => client.invalidateQueries(['user']),
})
```

* `onMutate` chạy trước khi mutation thực thi.
* Cho phép rollback nếu thất bại (`onError`).
* Giúp UI cảm giác “instant update” mà không chờ network.

---

#### 3.6. Mutation Deduplication

Khi nhiều mutation cùng `key` chạy song song:

* `MutationCache` merge chúng lại.
* Chỉ mutation đầu tiên fetch thật, các mutation khác reuse kết quả.
* Tránh ghi đè sai dữ liệu (giống TanStack).

### 4. Comparison Summary

| Feature                | TanStack Query | MFEStack Query                  |
| ---------------------- | -------------- | ------------------------------- |
| Query State Machine    | ✅              | ✅ identical                     |
| Mutation State Machine | ✅              | ✅                               |

### 5. Key Advantages of MFEStack

* Lifecycle tách biệt, dễ mở rộng & test độc lập.
* Retryer và Observer tái sử dụng chung giữa query & mutation.
* Hỗ trợ sync mutation chưa hoàn tất sau reload hoặc reconnect.
* Plugin layer có thể can thiệp vào lifecycle (DevTools, Logger, Metrics).
